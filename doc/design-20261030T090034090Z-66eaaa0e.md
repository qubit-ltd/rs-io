## 最小方案及取舍

只修改一个集成测试文件和两个 Rust 源文件中的 Rustdoc 正例。不改变生产函数体、trait 定义、公开 API、依赖、feature、文件组织或运行语义。不需要破坏兼容性，也不需要下游迁移。

不引入公共字符内存流类型：为了两个示例扩展 API 的维护成本明显高于收益。两个独立 doctest 各自定义小型局部输入类型，避免额外文件和对其他 crate 的依赖。生产 Rustdoc 的说明和示例注释使用英文，方案和计划使用中文。

### IO-001：在 trait object 外部观察输出状态

保留 `Box<dyn Output<Item = char>>` 测试边界，避免改成只测试具体类型而削弱原场景。将原局部 `CharOutput` 的数据和刷新状态改为共享观察句柄：

- `items: Rc<RefCell<Vec<char>>>`；
- `flushed: Rc<Cell<bool>>`。

这些标准库类型已经由同一测试文件导入，不添加依赖。测试持有观察句柄的克隆，`CharOutput` 的 `write_unchecked` 向共享向量追加内容，`flush` 设置共享标记。保持 `is_buffered()` 和原有全部调用及返回值检查。

每次写入后分别断言 `['b']`、`['b', 'c']`、`['b', 'c', 'd']`、`['b', 'c', 'd', 'e']`，在显式 flush 前断言标记为 false，之后断言 true。取回 inner 后再次检查累计内容、刷新状态和 `is_buffered()`。这样即使某个入口错误地只返回成功，测试也能定位到该入口。

所有检查均通过公开 API 和测试辅助对象的外部观察状态完成，不增加生产可见性或测试 hook。

### IO-002：两个独立的字符流完整示例

`AsyncCharInput` 的正例使用本地 `CharSlice` 实现公开 `AsyncInput`：持有字符切片和当前位置，只返回就绪结果。示例构造 `['你', '🦀']`，通过接受 `AsyncCharInput + ?Sized` 的辅助函数和 `Pin<&mut _>` 读取，断言 `Ready(Ok(2))`、具体字符及后续 EOF。使用 `Waker::noop()` 仅因为输入始终就绪，不展示没有唤醒机制的 Pending 实现，也不引入 Tokio 或 futures 执行器。

`SeekableCharInput` 的正例使用本地 `CharCursor` 实现公开 `Input<Item = char>` 和 `Seekable<Unit = char>`，不实现标准 `Read` 或 `Seek`，避免 blanket impl 冲突。使用 `['你', '🦀', 'a']`，定位到字符位置 1 并读取，验证得到 `🦀`；再通过 `&mut dyn SeekableCharInput` 辅助函数回到起点，读取并验证 `你`。例子清楚说明位置 1 表示第二个 Unicode scalar，不能解释成 UTF-8 字节偏移。

样例的 seek 实现用 `i128` 计算 Start、Current、End 偏移，拒绝越过示例有限区间的位置，避免负数或转换溢出。该限制属于示例内存流，不改变 trait 的通用 seek 契约。

两处保留 `# Examples` 标题及现有全部 `compile_fail` 反例；只替换正例并增加必要英文解释。样例从 `qubit_io` 公共路径导入，只在示例块内定义辅助类型，不访问 crate 私有项，不使用 `ignore` 或 `no_run`。保留非 Unpin 实现也可以满足 trait 的现有说明；本例采用易读的 Unpin 内存对象，不将其表述为 trait 的额外要求。
